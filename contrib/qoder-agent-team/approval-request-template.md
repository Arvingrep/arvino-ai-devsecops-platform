# 总监变更执行与集中汇报模板（单条红线后）

## 0. 规则

自 2026-10-21 起，红线只剩**不泄密/不输出密钥**一条。原“不花钱、不动架构决策、不碰生产集群写操作、不绕过 QA 门禁、不自己合并 PR”五条及 L0–L3 分级放行规则均已取消，见 `redline-release-policy-proposal.md` 与 `PROJECT_CHARTER.md` §3.3。

因此本文件不再是“逐动作审批”的闸门，而是：

1. **执行记录**：高风险或不可逆动作，总监在执行前后写明动作、版本、证据、回滚与结果，供追溯。
2. **可选知会**：总监判断需要 Arvin 知晓或拍板目标/预算时，用模板 A/B 发起知会；**知会不构成阻塞**，除唯一红线外不等待批准。
3. **集中汇报**：用模板 C 汇报结果，先结论后证据。

仍然必须做、但不再向 Arvin 逐条申请的事：CI/QA/安全门禁、独立验收、版本绑定、备份与回滚、变更留痕。这些是工程纪律，由总监与对应角色自行把关。

## 模板 A：高风险变更执行记录（知会可选）

```
【变更记录】<一句话说明做了什么>

1. 动作与目标
   - 动作：<部署 / 迁移 / 合并 / 停旧调度 / 业务仓库写 / 费用支出>
   - 项目与环境：<repo> / <env>（含 cluster/namespace/chain）
2. 绑定版本
   - commit / image digest：<sha / digest>
   - 配置变更：<key=value，敏感值只写键名>
3. 证据
   - CI：<链接或命令退出码>
   - QA（独立 tester）：<结论 + 证据路径>
   - 安全（适用时）：<结论 + 证据路径>
   - OPA/策略结果：<结论>
4. 风险与影响
   - 风险点：<>
   - 影响面 / 不可逆性：<>
5. 回滚
   - <具体回滚动作、触发条件、已验证结果>
6. 执行与结果
   - 执行时间：<>
   - 结果：<成功/失败 + 关键输出>
   - 未验证项：<>
```

## 模板 C：总监集中汇报

按 `TEAM.md` §8：只有**有效新证据**才汇报，不定时刷屏，不把子会话启动当进展。

```
【总监汇报】<一句话结论>

1. 结论
   - <一句话：做成了什么 / 卡在哪>
2. 证据与产物（绝对路径 + 命令结果）
   - <path>：<sha256 或指纹>
   - 命令：<cmd> → exit <n>，<关键输出>
3. 候选版本
   - <commit / digest / 快照指纹>；对应门禁结果：<>
4. 未验证项
   - <明确列出，不掩盖>
5. 阻塞
   - 类别（技术配置/模型/凭据/目标决策）：<条件> | 解除条件：<>
6. 需要 Arvin 拍板的事项（仅目标/预算/方向，不是逐动作审批）
   - <逐条；没有则写“无”>
```

## 纪律提醒

- 一次记录对应一个版本；版本变化后重新验证，不复用旧证据。
- 记录里不写“应该没问题”“预计无风险”这类无法核验的措辞；写“未验证项”。
- 不记录任何密钥、token、口令或完整环境变量值；只写键名/引用名。
- 变更记录只增不删，作为审计材料。
