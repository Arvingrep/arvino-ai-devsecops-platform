# 十角色注册与权限核验清单（供 UI 通道恢复后逐项执行）

## 0. 这份清单是什么

Task #8（核实十角色注册、权限与异构模型）曾因 Qoder UI 自动化通道被工具拒绝而阻塞：用户已明确授权，Computer Use 两次拒绝后不再重试、不旁路。**本清单是通道恢复后的执行脚本。**

**2026-10-21 更新：通道仍不可用，但用户改为手工 GUI 操作并已完成首批五个席位的注册与一次只读路由验收。** 本清单对应条目现以 `registration-verification.json`（结论 `passed_with_blockers`）为准，本文件继续作为**剩余条目的执行脚本**——§2 注册前只读核对、§3 注册执行、§4 异构模型条件、§5 通过判据中尚未打勾的部分，仍待完成或待证。

已核实与未核实的分界：不得凭配置文件推断运行状态。配置声明 ≠ 运行时强制；**账号侧存在 ≠ 模型异构已满足 ≠ 工具权限已强制**。

来源与已知边界（取自 `takeover-preflight.json` 的 `model_and_permission_documentation`）：

- 官方文档已说明：团队由 1 名负责人 + 1–4 名成员组成；成员需启用并绑定本机，团队任务要求设备在线；可选择自动档位或指定模型；自定义模型可出现在任务/Agent/自动化模型选择器；Credit 消耗与 token、档位、模型、工具调用相关。
- 已阅文档**未**说明：逐成员硬绑定模型家族、每次实际模型的可审计运行记录、逐智能体工具/文件路径白名单与 worktree 强制隔离、本地角色文件批量导入或注册 API。
- "未说明"不等于能力不存在；文档里的选项也不等于当前账号有资格。

## 1. 前置条件（不满足则本清单整体阻塞）

| # | 前置 | 判据 |
|---|---|---|
| P1 | Qoder UI 自动化通道可用 | 一次无副作用读取成功（只读，不点保存） |
| P2 | 目标机器设备在线、已登录 | 界面显示设备可用 |
| P3 | 未开启 Full Access、未改登录/订阅/凭据/生产权限 | 变更前后各读一次设置并留证 |
| P4 | 未产生付费模型调用 | 核验期间不跑业务模型探针；模型资格用界面显示而非调用验证 |

## 2. 注册前（只读核对，不写）

| # | 检查项 | 期望 | 证据 |
|---|---|---|---|
| R1 | 团队当前负责人与成员名单 | 与 `TEAM.md` 的十职责分工一致（不要求同时在线） | 界面截图/读回文本 |
| R2 | 席位上限 | 1 负责人 + 至多 4 成员；十职责靠"分阶段调用 + 释放完成席位"实现 | 界面读数 |
| R3 | 可选模型清单 | 记录**实际可见**的模型与档位（含订阅内可用项），不猜模型名 | 读回列表 |
| R4 | 角色导入方式 | 确认是手工创建、文件导入还是 API；记录"未文档化则标未确认" | 操作记录 |
| R5 | 工具/路径授权面 | 读出每个成员可用的工具清单与文件范围；**特别注意 Bash 是否可写盘、可联网** | 读回清单 |

## 3. 注册执行（每步只做一步，存证后再下一步）

| # | 动作 | 约束 |
|---|---|---|
| W1 | 创建负责人（总监） | 只配管理记录写权限；不得给 Full Access |
| W2 | 创建执行成员（按阶段补齐，最多同时 4） | 工具面按 `TEAM.md` §3 最小建议配置；不扩大 |
| W3 | 逐个绑定模型 | 只选 R3 中**已实证可见且在现有订阅内**的模型；不选按量计费项；不试探性调用 |
| W4 | 命名与说明 | 用 `roles.yaml` 的角色名与职责摘要，便于审计 |
| W5 | 每步后读回 | 保存每个成员的最终配置快照（名称、模型、工具面、文件范围） |

## 4. 异构模型条件（独立验收的硬条件）

TEAM.md §3 与章程要求：`tester` 与 `security` 的模型家族必须分别 `different_from_implementer`。要点：

- 判定依据是**实际运行所用模型家族**，不是角色名、会话 ID 或界面标签；
- 默认同模型子 agent **不满足**该条件；
- 若当前订阅内找不到可用的异构配置，记录为"模型阻塞"，**不擅自切换、不开付费探针、不谎称满足**；
- 每次验收需留：实现者会话所用模型、验收者会话所用模型、两者来源证据。

## 5. 通过判据

只有同时满足以下全部，才可把 `registration_status` 从 `prepared_not_registered` 改为已注册：

1. 十个职责的**配置**都已建立（允许分阶段，但每个职责都要有确定的映射记录）；
2. 每个成员的最终配置快照已留证（含模型与工具面）；
3. 异构模型条件有实证记录（若不满足，明确记为阻塞项而非勾选）；
4. 未开启 Full Access、未改登录/订阅、未授予生产或密钥访问权限；
5. 至少完成一次**只读**任务路由验证（不写业务仓、不改业务代码），证明路由与状态回读可用。

## 6. 记录位置与格式

每次核验写一份 JSON 证据（放本目录），至少含：核验时间、通道可用性、每个成员的配置快照、模型可见清单、异构判定、权限前后对比、命令/读回退出码、未核验项、结论。结论字段只允许 `passed` / `passed_with_blockers` / `blocked`，不允许 `assumed`。

## 7. 本次核验的只读范围（不是公司红线）

以下限制只适用于**注册核验这一轮**，用于保持只读、避免副作用；公司红线只有“不泄密/不输出密钥”。

不开启 Full Access、不改登录与订阅、不索取或打印密钥、不跑业务模型探针、不写业务仓库、不 commit/push/merge、不动旧调度、不清理他人工作区。
